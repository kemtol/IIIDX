## What Happened

`train_lightgbm.py` was re-run on `bsjp_v18_market_100d_fix/` without `--feature-modules-dir`,
training on only 112 monolithic L2 columns instead of the full 249 module features.
The resulting model (27 trees) **overwrote** what was in that directory.

A `_BAK/` directory existed at `model/BSJP/_BAK/bsjp_v18_market_100d_fix/` containing:
`model_lightgbm_opening_tp3.txt`, `metrics.json`, `walkforward_metrics.csv`,
`valid_predictions.parquet`, `feature_importance.csv`, portfolio charts.

**However** — `diff` confirms the `_BAK` model is byte-identical to `bsjp_v17_compound/`.
The backup is v17, not a genuine v18.  The original v18 model configuration (market order,
potentially different TP/SL) was **not recovered**.

## Root Cause: Data Divergence

### Hypotheses Tested (All Disproven)

| Hypothesis | Test | Result |
|-----------|------|--------|
| Regularization drift | Retrained with `--min-data-in-leaf 100 --lambda-l1 1.0 --lambda-l2 1.5` | Still 27 trees, AUC 0.622 |
| TP/SL thresholds | `label_tp` is pre-computed in L2 by `generate_datamart.py` (`overnight_return > 0.4%`), not in `train_lightgbm.py` | No effect on training |
| Weak trees (`num_leaves=31, md=500`) | Retrained with extreme regularization | Still 27 trees, AUC 0.622 |
| Guard filter removal | 3,725 rows out of 114,766 (3.25%) filtered — tested impact | Too small to explain 305→27 |
| Label distribution | Current L2: 37% positive rate, v17 folds: 36% — nearly identical | Not the cause |

### Confirmed Root Cause

**The underlying data changed.**  Every retrain attempt — regardless of hyperparameters —
produces exactly 27 trees at AUC ≈0.622.  This is the **optimal convergence point**
for the current (rebuilt) L2 datamart + L1 feature modules.

The original v17 was trained on a **different L2 datamart** generated by the
pre-27-Apr version of `generate_datamart.py`.  That file was modified on
27 Apr 12:48 — 4 hours after v17 was trained.  The v17 training session
used `generate_datamart.py` from before this modification.

Without git history, the exact diff is unknown.  Likely candidates:
- Feature module generation logic changed (column order, aggregation)
- Universe filtering changed (different ticker inclusion)
- Data source paths or join logic changed

## Preventive Measures

1. **`git init`** is the single most important missing piece.  Without it,
   every file overwrite is irreversible.
2. **Never train to an existing model directory** — create `bsjp_vN+1/` per run.
3. **Backup before every retrain**: `cp -r model/BSJP/bsjp_vN model/BSJP/_bak_vN_DATE/`
4. **Lock training scripts**: `generate_datamart.py` and `train_lightgbm.py` should
   have checksums recorded before modification.
5. **Reproducible pipelines**: Record the exact command + git hash used for each
   model version in `model/BSJP/bsjp_vN/run.sh` so it can be recreated.
6. **Separate L0/L1/L2 from model artifacts**: The retrain should never
   clobber training data that was used to produce prior models.
