## High-Level Decision

Training/research and production inference must use different data-handling paths.

| Path | Storage | Purpose |
|---|---|---|
| Training / research | Parquet | Historical archive, audit, retrain, full/batch L1/L2 rebuild |
| Production inference | DuckDB | Low-latency feature vectors, daily scoring, picks log |

Rule locked in:
- Do not use single-file L1/L2 parquet rewrite as default production inference path.
- Parquet remains source for training and backfill.
- DuckDB `features_store` is the production scoring store.

## Script Changes / Behavior Changes

`inferences/bsjp/fetch.py`:
- Now treated as fast vector-store updater, not full data builder.
- `--force` only re-upserts feature vectors into DuckDB.
- It verifies L1/L2 freshness.
- If target date is missing from L1/L2, it refuses slow rebuild by default.
- Slow rebuild requires explicit `--rebuild-l1` or `--rebuild-l2`.
- Deprecated `--skip-l1` / `--skip-l2` now only keep freshness verification semantics.

`inferences/bsjp/run.py`:
- Fixed read-only scoring bug.
- Previously opened DuckDB read-only when `--log-picks` was false, but still called `init_schema()` with `CREATE`.
- Now schema init only runs when `--log-picks` is used.

`inferences/bsjp/bootstrap_feature_store.py`:
- New script.
- Backfills canonical vectors from L2 parquet into DuckDB.
- Supports `--date-from`, `--date-to`, `--replace`.

`pipeline/feature/generate_broksum_datamart.py`:
- Added parquet date filters for raw broksum and yfinance reads.
- Added performance warning on single-file incremental L1 upsert.
- Still not considered production fast path because it reads existing L1 and rewrites merged output.

`edges/bsjp_overnight_sl2/scripts/train_lightgbm.py`:
- Docstring fixed from stale BPJS wording to BSJP overnight.
- Metrics `northstar` now writes BSJP overnight entry/exit metadata.

## Important Operational Clarification

The 3.35s fast-path benchmark is not raw L0 fetch -> L1 -> L2 rebuild.

It is:
- L1/L2 already fresh
- Extract target-date canonical vector
- Upsert DuckDB
- Ready for scoring

For a real market day with new OHLC/broksum:
- If L1/L2 are stale and the system falls back to single-file parquet generators, it can still be slow.
- The production-grade missing piece is a daily vector builder that reads latest L0 + warmup and writes directly to DuckDB `features_store`.
