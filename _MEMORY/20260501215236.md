## Bugs Caught by Real-Data Run (Would Have Been Missed by Synthetic Fixtures)

### Bug 1: DuckDB parser rejects `%` in unquoted column names

`master_broker` has `foreignfund_%`, `localfund_%`, `retail_%`. Unquoted DDL fails with `Parser Error: syntax error at or near "%"`. Synthetic fixtures used in B1/B2/B3 tests had only alphanumeric column names so this never surfaced.

**Fix**: `_q(name) = f'"{name}"'`. Applied uniformly across `create_table_sql`, `upsert_sql`, `readers._read_duckdb`. All identifiers double-quoted, even ones that don't need it. Continuity gate stayed green (4/4).

### Bug 2: Validator false-positive on timestamp columns

Source parquet stores `created_at` / `fetched_at` etc. as ISO **strings** (large_string in arrow). DuckDB casts them to TIMESTAMP / TIMESTAMPTZ on insert. Reader returns `datetime64`. `BaseValidator._compare_column` did strict `==` between str and Timestamp → 100% sample diff (773/773 on emiten, 92/92 on broker) even though values are semantically identical.

**Fix**: branch in `_compare_column` for TIMESTAMP-family types. `pd.to_datetime(utc=is_tz_aware)` normalizes both sides before equality. Post-fix validator returns `passed: true, sample_diff_count: 0` on both tables.
