## Design Decisions

1. **Per-table canary flags (not per-file)** — each fetch script has independent state via `L0_<SOURCE>_<FLAG>` env vars (e.g. `L0_MASTER_EMITEN_DUCKDB_WRITE=true`). PRD §12.5 shorthand "L0_MASTER_DUCKDB_WRITE" interpreted as full source name. Granular = better for canary, no cost.
2. **Audit cols auto-appended** — schema authors declare only user columns. `_inserted_at` / `_updated_at` injected by `TableSchema` helpers. Reserved column name check rejects accidental redeclaration.
3. **`now()` instead of `CURRENT_TIMESTAMP`** — DuckDB 1.5.2 has a parser bug: `CURRENT_TIMESTAMP` inside `ON CONFLICT DO UPDATE SET` is misparsed as a column reference (`Binder Error: Table "X" does not have a column named "CURRENT_TIMESTAMP"`). `now()` is semantically identical (both return TIMESTAMPTZ, autocast to TIMESTAMP). Documented in `_base.py` module docstring. Revert to PRD-canonical `CURRENT_TIMESTAMP` if DuckDB ≥ 1.6 fixes parser.
4. **`ipot_ohlcv_1h` excluded from `L0_SOURCES`** — still pending audit (carryover from prev session). Avoid dead config until decision is made.
5. **Frozen dataclasses** for `L0SourceConfig` + `TableSchema` + `ColumnDef` — static config, immutability prevents accidental mutation.
6. **`__post_init__` validators on both dataclasses** — fail fast on misconfig: both-write-flags-False, missing PK column, reserved audit name, duplicate column names.
