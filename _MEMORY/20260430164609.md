## Design Decisions (This Session)

1. **Two namespaces resolved**: 7 sources (table-level, canary flags) vs 6 db_files (file stems for ATTACH alias). `master_emiten` + `master_broker` share `master.duckdb`. Both forms accepted by `l0_path()` via `removesuffix('.duckdb')`.

2. **Atomic parquet write**: `_write_parquet` writes to `<path>.tmp` then `replace()` to final. No torn writes if process dies mid-write. Output byte-identical to direct `to_parquet(index=False)`.

3. **Writer transaction shape**: `CREATE TABLE IF NOT EXISTS` + `BEGIN` + `register('df')` + `upsert_sql()` + `COMMIT` + `CHECKPOINT` + `unregister('df')`. ROLLBACK on exception. CHECKPOINT after commit forces WAL flush so subsequent file size measurements are stable.

4. **No Python-layer flock**: rely on DuckDB single-writer file lock (fail-fast on accidental concurrent run) + planned shell `flock` per PRD §4.5.

5. **Reader audit-strip**: `read_l0` returns user columns only (drops `_inserted_at` / `_updated_at`). Downstream consumers see the same shape as parquet. Validator does the same drop before comparison.

6. **Backup tier scheduling = self-discovery**: daily cron, `tiers_for_date(today)` returns 0–3 tiers. First Sunday of January triggers all three (weekly + monthly + yearly). Yearly tier `apply_retention` returns `[]` (never delete). Single shell wrapper handles all tiers; no multi-cron complexity.

7. **`EXPORT DATABASE` over `pg_dump`-style export**: produces parquet directory + `schema.sql` + `load.sql`. `IMPORT DATABASE` round-trips exactly (verified: 2 rows in → 2 rows restored).

8. **Filename `0003_phase0_init.py` cannot be `python -m`**: leading digit blocks module-name resolution. Mitigation: `if __name__ == "__main__"` block with direct invocation `python pipeline/migrations/0003_phase0_init.py`. Future run scripts wrap that.

9. **Continuity gate auto-extends**: parametrized over `sorted(SCHEMAS.keys())`. When phase 1+ schemas land (`master_broker`, `global_indices`, ...), tests automatically grow without edits.

10. **No state tracking in `migrate.py`**: relies on idempotent SQL (`CREATE TABLE IF NOT EXISTS`). Re-running `init_all()` is safe. Phase 1+ migrations may add state if data-load idempotency requires it.
