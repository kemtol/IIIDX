# 2026-05-07 22:10 WIB - BSJP starter bootstrap recap mode

- **Scope:** Inference operations / first-day reporting.
- **Product:** Inference.
- **Intent:** Allow the first PnL recap push to include recent historical days, while keeping `picks_log` clean as the live walk-forward source.

## Changes

- Extended `pipeline/run/bsjp_pnl_recap.py` with starter-only bootstrap flags:
  - `--bootstrap-missing` scores missing recap dates with Go `bsjp predict` without `--log`.
  - `--bootstrap-fetch-missing-features` first runs Go `bsjp fetch --date D --force` when historical `features_store` rows are not executable.
  - Bootstrapped days and picks are labeled `[BOOTSTRAP]` in the message.
  - Data quality now reports starter bootstrap days explicitly and states they are not saved to `picks_log`.

- Extended `pipeline/run/run_pnl_recap_bsjp.sh` with opt-in env flags:
  - `BSJP_PNL_RECAP_BOOTSTRAP_MISSING=1`
  - `BSJP_PNL_RECAP_BOOTSTRAP_FETCH=1`

## Usage

- Normal clean mode:
  - `bash pipeline/run/run_pnl_recap_bsjp.sh`
- One-time starter push:
  - `BSJP_PNL_RECAP_BOOTSTRAP_MISSING=1 BSJP_PNL_RECAP_BOOTSTRAP_FETCH=1 bash pipeline/run/run_pnl_recap_bsjp.sh`

## Notes

- Do not leave starter env flags permanently enabled unless the message is intentionally allowed to include non-walk-forward bootstrap rows.
- The bootstrap mode is for initial communication only. Live performance should converge to `picks_log only` after enough daily inference logs accumulate.
