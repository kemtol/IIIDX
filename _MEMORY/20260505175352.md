## yfinance_1h timezone bug — confirmed

`pipeline/fetch/fetch_yfinance.py:152-156` (old) called `tz_localize(None)` after `tz_convert(LOCAL_TZ)`, producing WIB-naive timestamps. When `pd.concat([existing, fresh])` merged with later Go-written tz-aware rows, pyarrow promoted naive → UTC without shift, mislabeling 09:00 WIB as 09:00 UTC (= really 16:00 WIB).

Cutoff distribution:
- **2023-03-06 → 2026-04-27**: 734 days, all corrupted (UTC hours 9-16 in storage = real WIB 9-15).
- **2026-04-28 → 2026-04-30**: 3 days, mixed (Python WIB-naive + Go Jakarta-aware writing simultaneously).
- **2026-05-04 → 2026-05-05**: 2 days, correct (Go writer dominant).

**Fix-forward**: `clean_intraday` now keeps tz, normalizes to UTC. `_normalize_combined` casts to UTC tz-aware before write. New rows written correctly.

**Historical rewrite NOT done in this session** — mixed days require per-row dedup (not just shift). Deferred as separate follow-up. Inference impact: Go reads per-bar timestamps as raw UTC, hour-based grouping uses stored hour. Calibration was reportedly PERFECT for momentum/preclose14 (program.md v1.20) — investigate whether features land correctly despite shift.
