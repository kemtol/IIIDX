## Scope

Phase 0 prep untuk migrasi L0 raw data dari parquet → DuckDB per `_DOC/_PRD/0003_l0_to_duckdb.md`. Session ini cover: PRD writing (revision 0.1 → 0.4), dan eksekusi safety prerequisites (Phase 0 item #1–#4).

## Key Decisions Made (Session Ini)

1. **Storage architecture pivot**: parquet sebagai *frozen training snapshot*, DuckDB sebagai *working feature store* (sama dengan inference). PRD 0003 (L0), 0004 (L1/L2 working), 0005 (training snapshot) di-sequence.
2. **L0 topology = per-source DuckDB files** (bukan single file). Alasan: DuckDB single-writer-per-file lock — gabung satu file bikin fetch script paralel jadi serialized. Master digabung karena write frequency rendah.
3. **Canary by source**, 6 phase, 3 stage per source (dual-write → read switch → cutover). Dual-write minimum 14 hari kalender, read switch minimum 7 hari sebelum cutover.
4. **App-layer audit timestamps** (no DB trigger), explicit `CURRENT_TIMESTAMP` di setiap INSERT/UPDATE.
5. **Backup retention 3 tier**: weekly (last 4) + monthly (last 12) + yearly (archive, never delete).
6. **Validator tolerance per-dtype**: strict untuk int/string/bool/datetime, `np.isclose(rtol=1e-9, atol=1e-12)` untuk float.
7. **Broksum chunked migration per-minggu** (~200K rows/transaction, ~104 commit, dengan resume state JSON).
8. **Stockbit XL out-of-scope** untuk PRD ini — dia L1 derived dari broksum, masuk PRD 0004.
9. **Continuity test sebagai merge gate** (Precondition #4) — assert parquet output identik pre/post refactor dengan default flags. Wajib pass sebelum merge tiap fetch script refactor.
10. **DuckDB 1.5.2 pinned** di requirements.txt.
